# Portainer CE + Socket Proxy Stack

Docker Compose стек для развертывания панели управления Portainer CE с изоляцией Docker API через `linuxserver/socket-proxy`.

## Архитектура и безопасность

* Доступ к `/var/run/docker.sock` ограничен контейнером `socket-proxy`.
* Взаимодействие между `portainer` и `socket-proxy` изолировано во внутренней сети `socket_net` (`internal: true`) без публикации порта `2375` на хост.
* Оба контейнера работают с `read_only: true`, `cap_drop: [ALL]`, `no-new-privileges: true` и жесткими лимитами CPU/RAM/PIDs.
* Для ротации логов используется драйвер `local`.

## Требования

* Docker Engine >= 24.0
* Docker Compose >= 2.20 (используются теги `!override` и `!reset`)

## Быстрый старт

1. Загрузка репозитория в директорию со стеками:
```bash
git clone <URL_репозитория> /opt/stacks/core-portainer
cd /opt/stacks/core-portainer
```

2. Подготовка файла окружения:
```bash
cp .env.example .env
chmod 600 .env
nano .env
```

Обязательно указать внутренний IP-адрес интерфейса сервера в переменной `HOST_IP`.

3. Запустить стек (штатный режим через прокси):
```bash
docker compose up -d
```

Веб-интерфейс будет доступен по адресу `https://<HOST_IP>:<PORTAINER_HTTPS_PORT>`.

4. Инициализация и получение токена:

Откройте веб-интерфейс по адресу `https://<HOST_IP>:<PORTAINER_HTTPS_PORT>`.
Создание первой учетной записи администратора должно быть выполнено в течение 5 минут после старта. Для подтверждения прав система запросит токен безопасности.
Получите его из логов контейнера:
```bash
docker compose logs portainer | grep setup_token
```

Скопируйте хэш после `setup_token=` в форму инициализации и задайте пароль.
*(Примечание: если 5-минутный интервал истек, доступ будет заблокирован. Для сброса таймера выполните `docker compose restart portainer`).*

## Управление правами доступа и конфигурация

Архитектура стека позволяет гибко управлять уровнем доступа к Docker API. Настройка выстроена по трем уровням: от глобальных переключателей до полного отключения изоляции.

### 1. Глобальные профили безопасности (через `.env`)

Определяют базовые возможности веб-интерфейса Portainer. Регулируются переменными в корневом файле `.env`.

* **Ограниченный профиль (по умолчанию):** `PROXY_POST=0`, `PROXY_EXEC=0`.
  Разрешен просмотр метрик, логов, списков образов, а также управление статусом *существующих* контейнеров (запуск/остановка/рестарт). Создание новых ресурсов, удаление томов и доступ в консоль контейнера заблокированы.
* **Профиль администратора:** `PROXY_POST=1` и `PROXY_EXEC=1`.
  Разрешает полный спектр операций. Позволяет разворачивать новые стеки, скачивать образы и открывать терминал (`exec`) внутри контейнеров через браузер.

Для применения изменений после редактирования `.env` выполните:
```bash
docker compose up -d

```

### 2. Тонкая настройка фильтрации (через `socket-proxy.env`)

Статичная матрица разрешений HAProxy вынесена в конфигурационный файл `socket-proxy.env`.
Этот уровень позволяет точечно ограничивать права GUI независимо от глобального профиля. Например, чтобы запретить операторам читать логи или останавливать контейнеры, достаточно перевести соответствующие флаги `ALLOW_LOGS` или `ALLOW_STOP` в значение `0`.

Для применения изменений в матрице прав пересоздайте только прокси-контейнер:

```bash
docker compose up -d --force-recreate socket-proxy

```

### 3. Прямой доступ к сокету (отключение прокси)

Для администрирования без фильтрации API, предусмотрен запуск Portainer с прямым доступом к `/var/run/docker.sock`. Контейнер прокси при этом не запускается.

Активация через файл-оверлей:

```bash
docker compose -f compose.yaml -f compose.direct.yaml up -d --remove-orphans

```

> **Примечание:** Если Portainer ранее был инициализирован через прокси, после выполнения этой команды зайдите в веб-интерфейс (`Environments -> local`) и переключите тип подключения с `API` на `Socket`.

## Обслуживание

Обновление версий образов:

1. Изменить теги `PORTAINER_IMAGE` / `SOCKET_PROXY_IMAGE` в `.env`.
2. Выполнить:
```bash
docker compose pull
docker compose up -d

```
